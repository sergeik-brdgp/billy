# Self-review

**Решения.**

1. *Функциональное ядро и журнал до сети.* Логика — чистый редьюсер и контроллер над портами, без
   React/Expo; каждая фаза и ключ пишутся в SQLite до запроса. Поэтому ядро гоняется в Node против
   мока, а «второй job» и «ложное удаление» проверяются property-тестами. Цена — больше кода.
2. *Повтор POST.* ТЗ требует и «при гонке повторяйте POST с тем же ключом», и «без
   самопроизвольной повторной отправки» после relaunch. Решение: в той же сессии и только в
   foreground — не больше одного автоматического POST с тем же ключом после timeout/обрыва и 404
   по ключу; после перезапуска — только поиск по ключу. Цена: `createRequests` может быть 2 при
   `newJobs` 1.
3. *Foreground-загрузка с диска.* `UploadTask` стримит приватную копию; фоновая сессия могла бы
   создать job уже после локальной отмены. Проверка формата — правило `format()` мока по байтам
   (вердикты сверены дифференциальным тестом; клиент строже на байтах со старшим битом), размер —
   на копии, без чтения в память.

**Упрощено ради срока.** Один импорт за раз, нет фоновой загрузки и фонового polling, один экран без
навигации. Журнал на iOS в `Documents` попадает в бэкап, поэтому в нём только ключи, jobId, фаза и
размер: отчёт не пишется вовсе (после перезапуска берётся с сервера), имя — только пока сервер не подтвердил job. На
Android миниатюра «Недавних» скрыта с API 33, на 12 и ниже — нет. Остальное — в «Известных
ограничениях» [релизной записки](RELEASE_NOTE.md).

**Что сломается первым в production и как заметим.**

- Сворачивание во время загрузки на медленной сети: iOS прервёт передачу. Заметим по job без
  единого GET за 5 мин.
- Расхождение клиентской и серверной проверки формата при смене сервера: рост 415/413 на POST.
- Провайдеры `content://` с нестандартным потоком (pipe, облачные): «Couldn't read the file».
  Сейчас этого не видно — логи только локальные, нужен счётчик отказов чтения.

Пороги — в релизной записке. Дальше: фоновая загрузка с явной отменой, журнал вне бэкапа iOS, флаг
выключения функции.
