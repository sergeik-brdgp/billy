# Релизная записка: Statement Import 1.0.0

Expo SDK 58, React Native 0.88. В сторы не публикуется, `expo-updates` не подключён.

## Разрешения

- **Android (release):** только `INTERNET` (+ signature-разрешение AndroidX для своих ресиверов,
  пользователю не показывается). Файл приходит из системного picker'а (SAF) как один `content://`
  URI, поэтому `READ/WRITE_EXTERNAL_STORAGE` не нужны и заблокированы в `app.json`. Бэкап и перенос
  на новое устройство выключены: `allowBackup="false"` и правила `dataExtractionRules` /
  `fullBackupContent`, исключающие всё (плагин `plugins/withNoBackupRules.js`). Debug-сборка
  дополнительно содержит разрешения dev-клиента и cleartext HTTP для Metro и мока.
- **iOS:** запросов разрешений нет — document picker их не требует. ATS: только локальный HTTP (для
  мока); боевой API должен быть HTTPS.

## Где остаются копии файла

| ОС | Где | Когда удаляется |
|---|---|---|
| iOS | `tmp/<bundle id>-Inbox/` (копия системного picker'а) | сразу переносится в кэш приложения |
| iOS | `Library/Caches/imports/<opId>.bin` | когда сервер подтвердил job, при отмене, отказе и завершении |
| Android | `cache/imports/<opId>.bin` (потоковая копия из `content://`, обрыв на 10 МиБ + 1 байт) | то же |

На каждом холодном старте приложение удаляет копии без живой операции. Оригинал файла не меняется.
Журнал операций (`imports.db`, SQLite) хранит только ключи, `jobId`, ревизию, фазу, формат и размер;
отчёта в нём нет, имя файла — только пока сервер не подтвердил job. На iOS журнал попадает в
iCloud-бэкап (поэтому он минимальный), на Android исключён.

## Как очистить данные

1. Удалить импорт на сервере: «Delete import» и дождаться «All gone».
2. Локально: «New import» удаляет запись журнала; полностью — удалить приложение (iOS) или
   «Очистить хранилище» / `adb shell pm clear dev.narhi.statementimport` (Android).
3. Мок: `curl -X POST http://127.0.0.1:8787/__test/reset`.

## Сигнал остановки rollout

Стоп: больше одного job на один `Idempotency-Key` — признак второго job после повторной отправки.
Также: любые 409 на POST (ключ переиспользован с другими байтами); DELETE без `deleted` за 24 ч у
> 1 % импортов (пользователь думает, что данные удалены); рост 413/415 (проверка на клиенте
разошлась с сервером); падение crash-free / рост ANR больше чем на 0,5 п. п. к прошлой версии.
Откат — остановить поэтапный выпуск и выпустить предыдущую версию с новым номером сборки.

## OTA или новый бинарник

Сейчас любое изменение — новый бинарник (OTA не подключено). Если подключить:

- **Нужен новый бинарник:** добавление или обновление нативных модулей (`expo-file-system`,
  `expo-sqlite`, `expo-document-picker`, `expo-crypto`, `expo-font`, `react-native-safe-area-context`
  и др.), обновление Expo SDK / RN, `app.json` (разрешения, бэкап, bundle id, имя), config-плагины.
- **Можно OTA:** тексты, вёрстка, логика редьюсера и контроллера, таймауты, валидатор, адрес API.
  Исключение — смена формата журнала: без миграции откат OTA оставит новую схему старому коду.

## Известные ограничения

- Android 12 и ниже: миниатюра в «Недавних» показывает экран (`setRecentsScreenshotEnabled` есть
  только с API 33).
- Если `content://`-провайдер не отдаёт поток, файл копируется целиком и только потом проверяется
  размер (до POST всё равно не доходит).
- Проверено на симуляторе iOS 26.5 и эмуляторе Android 15; физические устройства и перенос данных
  Android на новое устройство не проверялись.
